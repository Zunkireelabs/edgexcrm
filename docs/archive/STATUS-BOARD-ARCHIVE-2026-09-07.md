### Archived: **Verified — fixed.** `command_timeout` is present in `deploy.yml`, `deploy-staging.yml` and `rollback.yml`.

- **Deploy-staging.yml silent-failure on Docker build.** The 2026-05-31 evening Phase 1 deploy hit a `docker compose build --no-cache` OOM (FATAL: heap allocation failure at 2GB cap; Dockerfile was running with `--max-old-space-size=2048`) but the workflow still reported "success" and the dev container kept serving stale pre-Phase-1 code. Two contributing factors: (a) `appleboy/ssh-action`'s script wrapper apparently doesn't reliably propagate non-zero exit from `docker compose build` despite `set -e`; (b) the Verify step (`curl /login`) returned 200 against the stale image — false positive (the new email API routes 404'd but /login exists in both old and new code). Fix landed for (a) via heap bump in `2952a3f`. **Open hardening**: harden the deploy script in `.github/workflows/deploy-staging.yml` (and mirror in `deploy.yml`) — wrap `docker compose build --no-cache` in an explicit `|| { echo "BUILD FAILED"; exit 1; }`, and harden the Verify step to hit at least one route that's known-new-in-this-commit (e.g., a build-info endpoint that returns the deployed commit SHA — could be a 1-liner GET). Without this, any future OOM or build failure could silently leave the dev/prod container on stale code with a green deploy badge.
